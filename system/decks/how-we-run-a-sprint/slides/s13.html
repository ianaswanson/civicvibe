Definition of done

Why have one

  • Everyone builds to the same bar
  • Drives communication and teamwork
  • Makes progress visible
  • Reduces complexity
  • Reduces technical debt

How to make one

  • The whole scrum team writes it
  • Review it at every retro
  • Keep it simple and short
  • Make it explicit
  • Use it daily
  • Include non-functional requirements

Ours

  • Acceptance criteria met
  • Code reviewed; tests pass
  • Accessibility checked with keyboard and screen reader
  • Security and non-functional needs met
  • In production, or deployable behind a flag
  • Release note and help content updated
  • Product owner accepts
The first two columns are from the earlier team's definition of done. The third is the definition of done in the user story template. Their software example had more items (SOLID refactoring, user manual); add what your team needs.
