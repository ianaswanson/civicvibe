Where we are, and where we want to be

What it feels like today

  • A request arrives as a solution: "we need a portal."
  • We build what was asked for, then learn whether it helped.
  • When it doesn't help, the work is already sunk.
  • Delivery dates get promised before anyone knows what to build.

Where we want to be

  • Start from an outcome, not a feature.
  • Hear from the people the service is for before we decide.
  • Try more than one idea, and test the riskiest part cheaply.
  • Commit delivery time only to what has earned it.

Most software fails because it's based on wishful thinking or fear. Discovery grounds the work in what's actually true.

The bold line is from the research plan in Ian's discovery notes. Ask the room for a time they built something nobody used.
