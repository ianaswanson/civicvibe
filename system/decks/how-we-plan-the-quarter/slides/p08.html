How we split our time

The split is set each quarter. Start from 50/25/25 and adjust to the work at hand.

Strategic 50%

Technical maintenance 25%

Small requests 25%

Adjust for the quarter

A fixed launch date may call for more Strategic. A system near end of life may call for more Technical maintenance. Write the split and the reason down.

Some teams differ for longer

A team mostly doing discovery might run 70/15/15. A team that mostly runs existing services might run 20/50/30.

Watch for patterns

If a team keeps overriding the default the same way, that is a signal. Change its default and say why.

Equal importance doesn't mean equal time. Each type gets protected time, so none of them quietly eats the others.

Example: the DMV team ran 60/20/20 in Q1 because of a fixed Q2 launch, and wrote that reason in the planning overview. Rule of thumb from experience: don't skip the maintenance session. One early planning gave it an hour, and the foundation slipped.
