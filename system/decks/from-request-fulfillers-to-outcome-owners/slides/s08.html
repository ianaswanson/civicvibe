Temporary efforts vs enduring value

Project

A temporary effort to deliver a specific output, like a system upgrade, a new feature, or an installation. It has a defined start and end.

Product (or service)

An ongoing thing you build that delivers value to people. It's ongoing and evolves.

Projects aren't the problem; they fit work with a clear end. Our problem: we also treat enduring services (like HR systems, data and analytics, or a resident-facing service) like temporary projects. We fund them, build them, and "operationalize" them, but the user's need for them is continuous, evolving and always increasing.

Swap in the services this audience knows best. Say the fit point out loud: a system upgrade or a hardware refresh is a project and should run as one. The trouble is running a service that never ends as if it will.
