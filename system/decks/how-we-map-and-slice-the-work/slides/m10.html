Releases start with a target outcome

What will people be able to do once this ships?

Write the outcome first

A user-focused statement of a new behavior or ability. "Users can request a basic ride with confidence."

Then pick the details

Only the details that make that outcome possible. Everything else moves below the line.

Cut across the whole map

A release can span many activities and tasks, but it must work end to end for someone.

Leave the activities in place

Even when nothing under an activity makes this release. The gap shows what this release won't do.

Releases reference details, not tasks, because details are what get built. From the v5 knowledge layer and doc 11.
