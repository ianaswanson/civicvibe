Five ways a detail goes wrong

Generate freely, then review for these, then fix only what's broken.

UI mechanics

"Tap map to set location"

"Specify pickup location"

Performance goals

"Load board quickly"

"Progressive rendering for large boards" (target under 2 seconds as a note)

Emotional outcomes

"Feel satisfied moving a card"

"Visual feedback when a card moves to Done"

Vague aspirations

"Easy to understand"

"Example cards showing usage"

Design constraints

"Create board without setup steps"

"Board created with sensible defaults"

The fix is always the same question: what specifically makes this true? Build that.

From the details protocol, v2: generate, review, refine. Keep details that are already good; make surgical fixes, not wholesale rewrites. A performance target or a feeling is a valid design goal; record it as a note, not as a detail.
